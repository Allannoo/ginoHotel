## 1. Краткое представление сервиса (elevator pitch — 30 секунд)

> **Горизонт** — современная облачная PMS-платформа (Property Management System) для отелей, гостевых домов и апартаментов в России и СНГ. Один календарь броней, единая база гостей, контроль финансов и команды, синхронизация со всеми каналами продаж. Мы помогаем небольшим и средним объектам размещения работать как сетевой бренд — без дорогих внедрений и многомесячного обучения.

---

## 2. Что уже сделано (фактическое состояние продукта)

- **Платформа**: React 18 + TypeScript + Vite, строгая типизация, dark/light темы, мобильная адаптация.
- **17 рабочих разделов**: дашборд с KPI (загрузка, ADR, RevPAR), календарь броней с drag-and-drop, объекты, каналы, гости (CRM), финансы, задачи (Kanban), сотрудники с гибкими ролями и правами, тарифы (RMS), расходы (OPEX), доставка в номер, умные замки, отчёты для МВД, аналитика.
- **Безопасность ролей**: 4 базовые роли + 15 гранулярных прав доступа, изоляция между владельцами объектов, журналирование действий.
- **Менеджер каналов**: готовая UI-инфраструктура для подключения OTA, детектор оверкуинга (overbooking), модальное окно разрешения конфликтов (апгрейд, перевод, партнёрский отель, компенсация).
- **Соответствие законодательству**: ФЗ-152 (персональные данные), отчёты для МВД, хранение данных на территории РФ.
- **Тесты и качество**: TypeScript strict, юнит-тесты (Vitest), автоматическая проверка типов в CI.

**Объём кодовой базы**: ~46 React-компонентов, ~28 TypeScript-модулей, ~15 000 строк кода.

## 6. Маркетинговое позиционирование (для презентаций и сайта)

**Заголовок**: Управляйте отелями и апартаментами как премиальная сеть.

**Подзаголовок**: Один календарь, один CRM, один менеджер каналов. Без таблиц, без хаоса, без двойных броней.

**Три тезиса**:
1. **Единый календарь** — все брони из всех источников в одном экране, drag-and-drop для перевода между номерами, мгновенное разрешение конфликтов.
2. **Менеджер каналов 2.0** — двусторонняя синхронизация с Яндекс Путешествиями, Островком, Суточно, Отелло, 101Hotels, Авито. Защита от оверкуинга на уровне платформы.
3. **Прозрачные финансы** — доход, ADR, RevPAR, расходы, прогноз и отчётность в одном кабинете. Без выгрузки в Excel.

**Социальные доказательства / маркеры доверия**:
- ФЗ-152, данные на территории РФ
- Гранулярные права доступа (4 роли × 15 разрешений)
- Журналирование действий и история изменений
- Готовность к интеграциям с электронными замками (TTLock, Igloo, SaltoKS, Nuki) и отчётностью МВД

## 7. База данных и реальная регистрация — техническая справка

> Сейчас регистрация и хранение данных полностью **локальные** (на устройстве пользователя, через `localStorage` + Zustand persist). Это удобно для демо и прототипирования, но недостаточно для production.

**Что нужно для «настоящей» регистрации**:

1. **База данных** — PostgreSQL (рекомендуется) или MySQL. На стороне Netlify сейчас БД нет: Netlify Hosting — это статический хостинг + serverless-функции. Опции:
   - **Netlify DB** (управляемый Neon Postgres) — самое простое, тянется одной командой `netlify db init`.
   - **Supabase** — Postgres + готовая аутентификация (email/пароль, OAuth) + хранилище файлов.
   - **Свой VPS** (Selectel, Yandex Cloud, Timeweb) с Node.js + Postgres + Redis.
2. **Бэкенд** — REST API (Node.js + Fastify/Express, либо Python + FastAPI). Минимально:
   - POST `/api/auth/register` (с bcrypt-хешированием пароля и подтверждением email)
   - POST `/api/auth/login` (JWT или сессионные cookie)
   - GET `/api/auth/me`
   - CRUD для объектов, броней, гостей.
3. **Безопасность**:
   - Хеширование паролей **bcrypt** или **argon2** (никогда не хранить в открытом виде).
   - HTTPS обязательно (Netlify даёт автоматически).
   - Лимит запросов (rate-limit), защита от brute-force.
   - Подтверждение email (письмо со ссылкой) — минимум против бот-регистраций.
4. **Платный тариф vs приглашения**: чтобы регистрация была не «свободной», а контролируемой, можно:
   - закрыть регистрацию за инвайт-кодами (генерируются админом),
   - или сделать allow-list по email/домену,
   - или модерируемое подтверждение (заявка → одобрение → активация).

**Рекомендация**: первая реальная версия — **Supabase** (быстрый старт, бесплатный план, встроенная аутентификация) или **Netlify DB + Netlify Functions**. Затем при росте — переезд на отдельный VPS / Yandex Cloud.
